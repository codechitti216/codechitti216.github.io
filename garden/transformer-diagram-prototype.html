The Problem

Before the Transformer, we had RNNs — an internal memory value that kept updating itself as the sequence went. But the issues were real: vanishing gradients made it impossible to learn from distant tokens, and every step had to wait for the previous one. GPUs with thousands of cores sat idle.

LSTMs and GRUs solved vanishing gradients with gating mechanisms. But they were still sequential, still slow, and long range dependencies still degraded over hundreds of tokens.

We needed an architecture that could look at any two positions directly — without marching through every step in between — and do it in parallel. That architecture is the Transformer.

From Tokens to Vectors

Turn token indices into dense vectors. A lookup table of shape (vocab_size, d_model), randomly initialized, trained with the rest of the model. Given token index 47, pull out row 47. Scale by √d_model so the embeddings are on a comparable scale with the positional encodings we'll add next.

Input shape: (batch, seq_len). Output shape: (batch, seq_len, d_model). The embedding layer adds the last dimension — that's the whole point.

Attention

We have our token embeddings. Multiply each by three learned matrices to produce a query (what are you looking for?), a key (what answer do I have?), and a value (what do I have to offer?).

Dot-product Q against all K's. Each dot product is a sum over d_k dimensions — variance grows to d_k. Divide by √d_k to normalize. Softmax turns scores into weights. Multiply weights by V — weighted sum. Each token comes out as a new vector enriched by the tokens that mattered most.

But Something Is Missing

"The dog attacked the cat" and "The cat attacked the dog." Same words, same embeddings, same Q, K, V. The attention scores come out identical. But these sentences mean completely different things.

Attention is a set operation. It has no idea that "dog" is at position 1 in one sentence and position 5 in the other. What's missing is positional information.

Positional Encoding

A function from position to a vector, added element-wise to each token embedding. Sinusoidal: computed from a formula using sines and cosines at different frequencies. Continuous, no length ceiling, and for any fixed offset k, PE(pos+k) is a linear transformation of PE(pos) — a rotation that lets the model learn relative positions.

Learned: a lookup table trained end-to-end. Simpler, more flexible, but limited to the max length seen during training. The positional OOV problem.

Now "dog" at position 1 and "dog" at position 5 produce different attention scores. The problem is fixed.

Multi-Head Attention

One softmax, one distribution that sums to 1 — a single head is forced to spread its total attention across all tokens. When multiple tokens need high attention for different reasons, the weights get diluted.

Split d_model into h heads, each with dimension d_k = d_model/h. Each head has its own W_Q, W_K, W_V and its own independent softmax. Head 1 focuses on "attacked," head 4 focuses on "dog." No dilution. Concatenate, project through W_O.

We don't design what heads learn. They specialize during training. Some redundancy is inevitable — many heads can be pruned with minimal loss.

The Transformer Block

Attention alone is linear — weighted sums. The FFN adds nonlinearity: expand to 4×d_model, GELU activation (soft-gates negatives instead of ReLU's hard zero), compress back. Attention reads the room, FFN thinks about what it read.

Residual connections: x + Sublayer(x). Gradient highway — one path always has gradient 1, regardless of depth. Layer norm: pre-norm keeps the residual path clean, post-norm forces gradients through it.

One block: LayerNorm → Attention → Add → LayerNorm → FFN → Add. Stack N of these. That's the encoder — bidirectional, every token sees every other token.

The Decoder

Same structure, one addition: a causal mask. The upper triangle of the attention score matrix gets set to -∞ before softmax. Future positions get zero weight. Each token can only attend to itself and tokens before it.

This is what makes the decoder autoregressive — generate one token at a time, each conditioned on everything before it. BERT uses an encoder. GPT uses a decoder. For tasks like translation, we need both.

The Full Architecture

The decoder has two attention layers per block: self-attention first (know your own history), then cross-attention (read the encoder). Q comes from the decoder, K and V from the encoder output.

Why self-attention before cross-attention? Without it, position 5's query only knows about the token at position 5 — it hasn't interacted with positions 1-4. Self-attention enriches the query with decoder context. Then cross-attention sends a meaningful question to the encoder instead of a context-blind one.

Stack N encoder blocks + N decoder blocks + linear + softmax. That's the Transformer.
